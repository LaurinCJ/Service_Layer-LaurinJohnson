LAYERS AND METHODS TO WRITE

Client -> API controller -> Business manager -> Data repository -> LocalDB.
No controller or client should talk directly to SQL.
Keep each model's files separate instead of placing everything in Program.cs.

For GameManager, FranchiseManager, and PlatformManager, write:
- GetAllAsync: return records from the corresponding repository.
- GetByIdAsync(int id): return one record or null.
- SaveAsync(model): insert when Id == 0; update when Id > 0.
  Decide how to represent validation errors and missing update targets.
- DeleteAsync(int id): return a useful success/missing/conflict result.
Validate inputs and convert SQL conflicts into useful application errors.

The data layer already implements separate Insert and Update methods.
Combining them as Save is the client-friendly business method you write.

In each controller, implement these URLs to match the supplied client:
  GET    /api/games             -> JSON array
  GET    /api/games/{id}        -> JSON object or 404
  POST   /api/games             -> Save (insert or update using body Id)
  DELETE /api/games/{id}        -> delete, or 404/conflict
Repeat for /api/franchises and /api/platforms.
Return Created/OK for successful saves and NoContent for successful deletes.
GetAll should return [] for an empty table, not 404.

Suggested service model properties (you decide and implement):
  Game: Id, Title, Notes, ReleaseYear, FranchiseId, PlatformId;
        optionally FranchiseName and PlatformName for display.
  Franchise: Id, Name, Developer.
  Platform: Id, Name, Manufacturer.
DTO/service models are separate from SQL objects so you choose what clients see.
Keep your property names compatible with your POST request bodies.

The console client uses HttpClient and displays JSON. It calls every table's
list and single-record endpoints without needing a browser or CORS policy.
It intentionally does not implement insert/update/delete calls for Project 5.
Those operations must still exist in ALL THREE backend layers.
If you add a browser client later, configure CORS for its actual origin.
In your reflection describe what happened truthfully; do not invent CORS issues.
